# Architecture: Content Extensibility

New maps, character designs and weapons will be added often, so adding content must not require changes to core scripts.

- **Maps**: each arena is a self-contained scene under `scenes/arenas/` that owns its geometry, `SpawnPoints`, `ItemSpawns` (`ItemSpawner` nodes) and `Camera2D`. The main scene only loads an arena. A map's `camera_limits` are exactly 640x360, 1280x720 or 2560x1440 (the view at a camera zoom), and the map maker places `CameraShot` nodes (composed views at zoom 3, 1.5 or 0.75) that the camera cuts between; `test_arenas` checks every arena scene. The Docks (`docks.tscn`) is built by `tools/make_docks_arena.gd` from an ASCII layout (change the layout there and rerun, not the scene); the test arena stays for tests. Until movement is right the game loads the Range (`range.tscn`, user, session 4): a flat 640x360 floor, two barrels and measuring lines every 8 px (`measure_grid.gd`), no background. Map props (`Ladder`, barrels) are scenes under `scenes/props/`; one-way platforms are tiles with one-way collision.
- **Characters**: one shared `Fighter` scene; a character is a `CharacterData` resource under `data/characters/` (its look) that points to a `FighterClass` resource under `data/classes/` (how it fights: melee combo, later class stats).
- **Weapons**: one shared `Weapon` scene; a weapon is a `WeaponData` resource under `data/weapons/` plus its sprite. Weapons are separate sprites attached to the fighter's hand, never baked into character frames.
- Prefer a new resource or scene over a new code branch when adding content.

# Architecture: Code Rules

- Small, focused scenes and scripts. Movement, combat, weapons, health and animation stay separate.
- Damage and hit detection never depend on sprite art (collision shapes and shape queries only).
- Fighters never read `Input`; a controller (local, bot, remote) provides their intent.
- Use signals where they simplify communication; avoid unnecessary abstractions and dependencies. Use Godot's native 2D physics and animation.
- Build one milestone at a time, run the checks after each one, and do not add features that were not requested.

# Art Pipeline

- The user draws the art in their own working folders (`characters/`, `weapons/`; untracked, never commit them unasked). The PNGs the game uses are copied into `assets/`; item art is 3x (`ItemData.pixels_per_unit`). Textures import with mipmaps (project importer default) because the camera shrinks the art when it zooms out.
- Any art generated by script keeps its `.aseprite` source under `art/`, exported to `assets/` with the Aseprite CLI (`C:\Program Files\Aseprite\Aseprite.exe -b ... --script file.lua`).
- The players are stick figures (user, session 4: the drawn characters are set aside). Their animations are frame by frame: `tools/make_stickman.gd` samples every keyframe clip at 24 fps (at least 12 frames a loop) and draws each frame as its own picture (white body for the character colour, shaded far limbs, dark outline, smears behind fast hands and feet) into `art/stickman/strips/` with a `.json` per clip (timing, front fist per frame) in `assets/characters/stickman/`; then `tools/stickman.lua` (Aseprite CLI) saves one `.aseprite` per clip in `art/stickman/` and exports the strips to `assets/characters/stickman/`. Attack clips also get an untinted `<clip>_fx.png` strip (white wind behind the strike), played behind the body. Rerun both after changing a clip. `FrameAnimator` plays them (`CharacterData.frames_dir`).
- Character animations are keyframe clips in `assets/animations/` (format: `docs/CHARACTER_ANIMATION_SPEC.md`), played by `RigAnimator`. Clips Claude makes come from `tools/make_animations.gd` (`<godot> --headless --path . -s res://tools/make_animations.gd`); change the generator, not the JSON. Motion capture sources (CMU BVH) live in `art/mocap/` and are read by `tools/mocap.gd`; `test_clip_anatomy` checks the captured locomotion clips.
- Map art (the Docks tiles, props and background) comes from `tools/draw_docks.lua`, sources in `art/docks/`. The PixelLab Aseprite extension is GUI-only (it fails in `-b` batch mode), so Claude cannot drive it.
- `images/` holds reference screenshots only; it is excluded from Godot import (`.gdignore`), as is `art/`.

- Run every suite (Git Bash): `tests/run_all.sh`; one or more: `tests/run_all.sh test_melee test_pickup`. Exit code 0 = all passed.
- A single suite by hand: `<godot> --headless --fixed-fps 60 --path . -s res://tests/<test_name>.gd`. `--fixed-fps 60` runs physics as fast as possible instead of in real time (about 12x faster).
- Suites extend `tests/test_case.gd`, which fails the suite on any engine or script error, not only on failed checks.

# Commit Conventions

- Split work that would normally fit in a single commit into 4-5 small, logically separate commits.
- Each commit must be atomic: one concern per commit (e.g. scaffolding, core logic, tests, docs, config), and the project should build and pass checks after every commit.
- Follow the global message rules: imperative mood, subject under 72 characters.
